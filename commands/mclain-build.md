# McLain Build

Use the `mclain-systems-builder` skill.

Do not stop at advice. Move the request toward a durable asset.

For the supplied input:
1. Identify the real operator outcome.
2. Inspect the available repository/project context before inventing structure.
3. Strengthen weak requirements where necessary.
4. Define source of truth, interfaces, and acceptance proof.
5. Build or specify the smallest durable system that can expand.
6. Add automation and recurring-value loops where they materially help.
7. Prefer mobile-first operating surfaces for operator workflows.
8. Finish with the exact next executable action and proof required.

If tools permit implementation, implement instead of merely describing implementation.
